# BUSINESS_RULE.md

## BR-001 專案定位

本系統為美髮沙龍商品叫貨系統，不得改造成餐飲點餐系統。

## BR-002 商品排序

商品依商品代號排序。

## BR-003 商品代號

商品代號為商品識別值，應保持唯一。

## BR-004 購物車唯一鍵

```text
商品代號 + 客戶名稱
```

## BR-005 覆蓋規則

若商品代號與客戶名稱皆相同：

- 覆蓋數量
- 覆蓋付款方式
- 不新增第二筆
- 不累加數量

## BR-006 不同客戶規則

若商品代號相同，但客戶名稱不同：

- 保留為不同購物車項目
- 送出時分成不同資料列

## BR-007 數量規則

- 必須為正整數
- 最小值 1
- 最大值 99
- 不接受 0
- 不接受負數
- 不接受小數
- 同商品同客戶再次輸入時直接覆蓋

## BR-008 付款方式

只允許：

```text
已付款
未付款
自領
```

## BR-009 客戶名稱

客戶名稱為必填，可包含半形或全形數字；不合規資料不得加入或從購物車還原。

- 必填
- 去除前後空白
- 不可只含空白
- 可包含數字（見決策 D-014）
- V1 不自動拆解姓名內容

## BR-010 LINE 訊息格式

固定格式：

```text
商品代號 數量 付款方式 客戶名稱
```

例如：

```text
A02 10 已付款 小明
```

不可加入額外標籤、冒號、商品名稱或備註。

## BR-011 多筆格式

每筆一行：

```text
A02 10 已付款 小明
A08 2 自領 小華
```

## BR-012 向下相容

所有修改必須保持：

- LINE Bot 相容
- Google Sheet 相容
- 統計流程相容
- Excel 匯出相容

## BR-013 V1 禁止項目

V1 不加入：

- 備註
- 價格
- 會員
- 優惠券
- 餐點
- 庫存扣帳

## BR-014 叫貨狀況權限規則

一般設計師只可查看自己 LINE User ID 對應的目前 ORDERS；管理員可查看全部。身分必須由後端向 LINE 驗證，前端不可自行宣告管理員；API 不回傳 LINE User ID，也不修改 Sheet。

快取只存放於目前瀏覽分頁、最長五分鐘，不保存 access token；重新整理失敗時不得清空已顯示的成功資料。
